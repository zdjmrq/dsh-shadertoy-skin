# 0.4.7 — 每背景独立设置与音乐连续播放

- **每个背景记住自己的设置**：除「启用背景」仍是全局开关外，不透明度、透明档、亮度、模糊、分辨率、帧率、播放速度、画面/音乐循环、音量和静音都按作品分别保存。切换作品恢复该作品的选择；「本背景恢复默认」只影响当前作品。
- 状态升级为 **v3**：v1/v2 旧配置自动迁移，升级前实际看到的外观原样保留；旧全局选择作为尚未单独设置作品的初始基准。旧项目副本里已失效的全局字段会被修正，迁移后独立修改不会反写基准。
- **音乐连续播放**：迟到的音频块不再被整块丢弃或截掉块首，而是重映射设备时钟后完整播放；合成提前量 0.4 → 1.2 秒；Worker 计入消息传输延迟，繁忙渲染后不会继续按陈旧时钟供数。
- **1× 自动联播以实际听到的音频位置驱动画面**，渲染卡顿或缓冲恢复后不再累积音画偏移；联播静音尾段保持静音，接缝淡入淡出不变。
- **修复设备被自动播放策略阻塞后解锁会把画面拉回开头**：首次真正出声时从当前画面位置加入音乐，而不是把画面拽回 0。
- 设置页显示真实联播周期与等待秒数（如 Take On Me 画面 209 秒 / 音乐 180 秒 → 按 209 秒联播，音乐播完后等待约 29 秒再共同重播）；播放信息来自运行中的播放器，不依赖静态标注。
- 旧 Host 仍在运行旧模块时，设置页会明确提示「完全退出并重新启动 DSH」，不会用旧校验规则悄悄丢弃新参数。
- 诊断快照新增音频设备缓冲秒数（`queuedSeconds`）与断粮恢复次数（`underruns`），便于区分性能断流和正常片尾等待。
