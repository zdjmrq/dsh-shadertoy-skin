## 本轮修复

| 范围 | 发现的问题 | 处理与验证 |
|---|---|---|
| 源码与参数竞争 | `preset` 后紧随的 `params` 消息会使源码读取失效，新建/编辑项目可能仍运行旧背景 | 源码读取与参数版本分离，读取总能更新作品库，同时保留较新的实时参数；端到端断言保存后实际运行新项目 |
| 音频暂停 | 生产者时钟包含预缓冲，隐藏/暂停后从该时钟续播会跳过未播放片段 | 记录每个 WebAudio 源的时间段，从实际听到的位置重建；验证暂停、恢复和时长调整 |
| 音频生命周期 | 调整音乐模式可能按提前的生产者时钟截尾；渲染失败后定时器可能继续 | 重新排队未播放尾段，错误后停止定时器；恢复与一次播放回归继续通过 |
| 音频采样 | 像素中心偏移半个采样，RGBA 字节打包可能被 dither 修改 | 按采样零点生成，打包时关闭 dither，并恢复 GL 状态 |
| GLSL 兼容 | 原生 `main()` 绕过亮度和遮罩；自定义输出、Common 中辅助 `mainImage`、精度限定 uniform 可能重定义 | 包装真实 main，识别输出变量，兼容 ES1 回退；验证实际 GPU 像素值 |
| 数据 Buffer | 图像过滤不能用于状态缓冲，否则坐标、负值、HDR 和体素编号会截断 | Buffer 独立编译，最终 Image 才应用外观；用体素位置检查验证保留完整浮点数据 |
| 保存反馈 | 导入在落盘前报成功、失败后清空粘贴输入；代码页的普通重试可能误存代码 | 等待保存成功后报告；失败保留输入；分开状态重试和代码重试 |
| 删除事务 | 延迟删除/回滚可能与切换、代码保存竞争；失败删除可能残留在恢复记录 | 删除期间禁用该面板编辑并取消旧激活；回滚同步恢复记录；验证失败后重开不删作品 |
| 旧偏好迁移 | 已存在部分全局设置时，其余旧全局偏好未迁移 | 按字段合并活动作品的旧偏好与显式全局值，显式选择优先 |
| 编辑器换行 | Windows CRLF 在 textarea 中归一化后，未编辑的项目被误标为未保存；Sound 保存时 trim 也会制造假草稿 | 共享源码归一化为 LF，保留实际编辑文本的空白；新增初始干净状态断言 |
| 损坏状态 | `settings` 等字段为字符串时 Host 验证后仍把原文件交给前端，可能阻止启动 | 报告损坏并保留原文件；不按空库覆盖；忽略无效的本地恢复记录 |
| 本地资源与开发工具 | 开发服务器绕过正式 Host 的真实路径检查，导入解析与正式环境不同 | 共用正式只读路由、符号链接边界和项目解析；持久化必须显式启用临时 profile |
| 桌面交互 | Electron 不应依赖 `window.prompt()` 创建文件或改名 | 改为插件内的输入栏与确认按钮；文件标签支持键盘导航 |
| 卡死与崩溃 | 同源 iframe 的重型编译与 readPixels 仍可能阻塞 DSH 界面线程；重载恢复可能形成崩溃循环 | 编译、渲染、读回与合成移至 Worker；30 秒编译 / 12 秒运行无心跳即终止；重复初始化合并、切换取消旧编译；一分钟内重复 GPU 崩溃熔断；故意阻塞 Worker 验证界面按钮可点击和切换后恢复 |

## 多文件系统

`native-dist/project.js` 由 Host、导入器、编辑器与播放器共用。`code.image` / `code.sound` 保持兼容，新增 `common`、`buffers`、`includes`、`assets`、`channels`、`duration` 与 `bufferSettings`。整个项目作为一个条目导入、保存和导出。

支持文件夹、多文件选择与 ShaderToy JSON；导入界面可确认文件角色和四路通道。上方文件横条支持选择、新建及删除 Common、Buffer、Sound、include 文件。源码草稿和读写操作覆盖整个项目。无法仅凭 GLSL 确定通道关系，导入建议后仍允许手动调整，避免把所有文件拼成一个 mainImage。

Buffer 按 A–D 执行，自身与后序 Buffer 读取上一帧，前序 Buffer 读取当前帧；使用双缓冲，避免 WebGL 反馈读写同一纹理。重播、重置与尺寸变化会清理或重建反馈，并重置帧号。纹理支持内嵌 PNG/JPEG/WebP、离线字体、2D/3D 噪声、程序化城市及键盘；键盘只在独立预览响应，DSH 嵌入背景不截获键盘。

文件名、输入引用、图片类型和尺寸均校验；include 拒绝越界、循环与过大的展开。错误项目保留上一有效画面。Cubemap、外部视频/音频输入仍明确不支持。

## 新增内置项目与性能

| 项目 | 结构 | 检查与优化 |
|---|---|---|
| Take On Me | Common / A / Image / Sound | A 的 alpha 携带 24 位打包深度，保留 RGBA32F；不生成无用 mip；保留原步数和声部；离线字体同时提供覆盖率与 SDF 通道 |
| Never Gonna Give You Up | Common / Image / Sound | 共享代码分开保存，编译时组合；177 秒结束点；保留原声部 |
| 下雨的窗户 | Image + 图片 | 补充离线程序化城市纹理与 mip，雨滴计算保留；102 秒结束点 |
| 赛车 | Common / A / B / Image / Sound | A/B 半精度，不生成无用 mip；删除 B 中随即被覆盖的首次纹理采样；保留反馈与镜头采样 |
| 我的世界 | A/B/C/D / Image | 状态保留 RGBA32F / 最近邻 / 无 mip；修复静止时摩擦除零污染持久状态的 NaN；验证位置保持有限值且高度未截断 |
| 风中的树 | Common / 阴影 A / 反馈 B / Image | 阴影保留完整精度；颜色反馈用半精度，仅 B 为实际使用的高 LOD 模糊生成 mip；接通 3D 噪声 |

相同尺寸下，RGBA16F 的基础缓冲数据量为 RGBA32F 的一半。去掉不用的完整 mip 链还可避免约四分之一的该缓冲存储和每帧生成工作。这是格式和资源计算结果，不代表任意显卡帧率提高相同比例。未通过砍掉人声、射线步数或模糊采样来声称等价加速。

主画面最多 800 万像素，分辨率选项共用运行时预算计算。所有 Buffer 合计约 96 MiB 数据预算，超出时等比例缩小离屏缓冲；图片合计 1600 万像素。缓存 GPU 尺寸限制与通道数组。已知有限时长的音乐静音或音量为零时，跳过昂贵的 GPU 合成但保留播放时钟和循环；未知时长继续采样以保持结束检测有效。音乐参数/静音跨零变化时，从听到的位置重新排队。

本机 SwiftShader 小窗口检查记录：Take On Me 单缓冲约 1.8 MiB、赛车双缓冲约 1.8 MiB、树木双缓冲约 2.9 MiB（320×180）；体素四缓冲约 28.1 MiB（640×360）。诊断中的 submissionMs 是 CPU 提交开销，不能作为 GPU 帧耗时。复杂项目在高分辨率、软件渲染或不同驱动下仍可能很重。Worker 隔离可停止无响应的渲染任务，但无法保证第三方 GPU 驱动或浏览器 GPU 进程绝不出错。

## 后续优化空间

可继续做按显卡预算自动分辨率、编译缓存/异步编译、更多通道采样器设置、资源图可视化、背景库搜索排序及完整配置备份恢复。任意 GLSL 的自动结束检测仍是启发式，复杂项目可用时长提示或手动模式。独立的两个 Host 同时写同一个 DSH_HOME，目前仍需额外的跨进程协调；当前队列和 ETag 针对单 Host/多窗口，不应据此宣称跨进程锁已实现。
