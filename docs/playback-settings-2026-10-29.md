# 音乐连续播放与独立背景参数（2026-10-29）

## Take On Me 的停止点

原作 `sound.glsl` 的 `mainSound` 明确包含 `if(time<0.||time>=180.)return vec2(0.);`。排查时仅在临时测试环境绕过播放器的时长限幅，直接采样原作输出：179 秒仍有声音，180、181、185、195、208、210 秒均只剩 16 位编码的零值量化噪声。内置项目的音乐 180 秒、画面 209 秒标注与此一致。

保持原有 1× 自动联播结构：音乐播放完后等待约 29 秒，音画一起重播。**未修改任何内置着色器或时长标注，也没有改成独立循环。** 设置页现在明确显示等待秒数。非 1×、手动画面循环和音乐只播一次的原有行为保留。

这能解释片尾静音后从头重播，不能证明用户报告的所有半小时播放异常都来自原作。本轮没有声称完成 DSH 原窗口的半小时实听复现。

## 插件侧修复

- 原控制器会丢弃整块迟到音频，或用 offset 截去块首。现在调整设备时间与合成时间的映射，按顺序完整播放迟到的数据；缓冲耗尽造成的已发生静音无法消除，但恢复后不再跳过乐句。
- 合成提前量由 0.4 秒增至 1.2 秒，块大小、合成采样率和 32 块设备队列安全上限不变。持续合成速度没有提高，只增加有限缓冲。
- Worker 收到音频时钟时计入消息传输等待时间，避免繁忙渲染后仍按陈旧时钟供给数据。
- 1× 自动联播以实际听到的音频位置驱动画面，避免只设相同周期、两个时钟仍长期漂移。缓冲恢复和共同回绕均保持这个关系。
- 诊断快照增加设备缓冲秒数、断粮恢复次数，便于后续区别性能断流和正常片尾等待。

## 每背景独立设置

除了启用背景是全局开关，外观、性能、画面播放、音乐播放、音量和静音都按项目 ID 保存。切换作品读取该项目参数；恢复默认仅重置当前项目。

状态升级为 v3。迁移 v1/v2 时，旧全局外观继续作为未设置作品的初始基准，并覆盖旧项目副本中已失效的全局字段，以保留升级前实际看到的外观。迁移后项目参数优先于初始基准；独立修改不会反写旧基准。恢复默认显式写入当前默认参数，避免回落到旧基准。

Host 健康信息声明 `stateVersion: 3`；设置页需要该协议，旧 Host 仍在运行时要求完全重启，禁止编辑写入。失败保存的本地日志也走同一迁移路径，ETag 与原子写入机制继续保留。

## 验证

- `npm test`：包检查 419/419、TypeScript 检查、Host 状态协议和项目格式测试。
- 全部 16 个浏览器套件：renderer、audio、panel、ui、audit、core、project、multi、worker、editor、surfaces、transparency、startup、playback、interaction、community。
- `test:playback` 新增真实 WebAudio 数据检查：模拟 PCM 按顺序迟到 1.9 秒，验证播放 offset 为零、相邻块样本连续、设备时间有序、恢复后音画误差小于 0.2 秒。用旧控制器运行同一场景可复现块首被截去，新控制器通过。
- 独立参数覆盖旧配置迁移、切换、整页重载、恢复当前作品默认、全局开关和失败保存恢复。原有多窗口冲突、编辑器、主题、鼠标/键盘隔离测试同步验证。

测试使用临时 DSH 服务适配器和 Edge 浏览器，没有改写用户的已安装 DSH 配置。
