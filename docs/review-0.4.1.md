# 0.4.1：文件标签编辑器与保存连接修复

## 界面

- 背景库的粘贴导入区和代码页均改为单个可见代码编辑区；默认 Image、Sound 两个文件标签和 + 创建按钮。
- 移除“全部文件”模式，多文件项目按已有文件生成标签。Common、Buffer A–D、include 的创建逻辑由两个界面共享。
- 通道配置放在代码框下方的折叠区；粘贴多 pass 项目也能指定通道。删除 Buffer 同时清除其通道引用和渲染配置。
- 普通标签切换保留编辑内容、光标、选区和滚动位置；粘贴草稿支持会话恢复，保存成功后清空。
- 文件标签支持键盘方向键/Home/End，窄屏横向滚动。保留字号、换行、行号、专注编辑和高度记忆。

## 保存故障定位

原实现给所有小于 60,000 字节的 PUT 设置 `keepalive:true`，只检查了单次请求大小。浏览器实际限制是共享的 64 KiB 在途 keepalive 请求额度；占用额度时，一个正常大小的保存请求也会被浏览器直接拒绝。旧 catch 将所有异常归为“Host 路由不可用”，无法解释实际原因。

新回归测试在真实 Chromium 内占用 60,000 字节额度，再发 10,000 字节 keepalive 请求，确认浏览器拒绝；相同额度占用下，新的普通保存仍写入真实 Host 和磁盘。此复现确认原代码存在可触发该提示的缺陷，不能据此认定用户此前每一次同文案错误均来自该原因。

- 普通保存取消 keepalive，每次请求设置 12 秒超时。网络异常及 502/503/504 最多自动重试一次。
- 每次逻辑保存使用唯一请求 ID。Host 在原有串行写入队列中记录最多 128 个成功回执。重复 ID 仅在内容相同且磁盘仍处于该保存结果时返回原 ETag，不再次写盘；不同内容或后续修改返回 409。
- 回执仅保存在当前 Host 进程内；Host 重启后无法识别此前请求时，ETag 仍阻止覆盖新配置，用户需要重新加载确认。
- 原有原子落盘、ETag 冲突保护、失败草稿与恢复日志继续使用。连续断连自动重试达到上限后停止，避免后台无限保存。
- 离线、超时、无响应、HTTP 权限/路由/容量/Host 错误分别提示；Host 写盘错误仅返回允许的磁盘错误码，不泄露路径。在线但未收到响应不能直接归因于网络，提示检查网络与 Host。
- 代码和粘贴页传递具体保存原因；重试同一次未成功的粘贴导入不重复创建作品。
