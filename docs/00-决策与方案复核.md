## 0. 一句话结论

**能做，而且比原方案写的更稳。** 原方案的「Runtime 自研 + iframe + 半透明玻璃 + 背景库」四件事全部成立；但 **M0 的注入机制要换**（`webserver/index-inject` → `dsh.client` Client 插件 + Host 静态路由），否则每次改代码都要整机重启、而且拿不到动态主题能力。
剩下唯一没实测的生死点：**把 DSH 界面变半透明后，shader 能不能真的透出来、文字还能不能读** —— 机制已确认可覆盖（AppFrame 的表面颜色全部走 CSS 变量），M0 第一天就能验证。

## 1. 原方案：哪些成立、哪些要改

| # | 原方案说法 | 结论 | 修正 |
|---|---|---|---|
| 1 | 「背景层靠 `webserver/index-inject` 注入」 | **真实存在，但不该选** | 桌面版 index 注入表是 **Host 启动时采集一次的 IPC 快照**（`dsh-desktop-host/lib/index.js:342-349` → `main.js:12138/12193/12424-12431`）→ 改一次注入行、装一个新插件都要**整机重启**；Web 端才是每次渲染重收。→ 改走 Client 插件（可热更、能调 theme 服务） |
| 2 | 「注入行不能用 `kind:'script-src'`」 | **半假** | 框架自己就用它注入 bootstrap 批（`dsh-client-modules:494-498`）。真雷是桌面解释器会 `await` 它，加载失败直接 reject boot readiness → 主进程 fatal。→ 结论（别把关键脚本放 script-src）可沿用，理由要改 |
| 3 | 「注入监听器必须在 apply() 里同步注册」 | **成立（有前提）** | 因为桌面注入表只有启动时那一次采集机会 |
| 4 | 「背景层必须挂 body 首子节点，否则破坏 DOM 水合」 | **做法对，理由是错的** | `#root` 是空 div + `createRoot`（不是 hydrate，没有水合）。真实原因：① `#root` 归 React 独占，塞进去会被清掉；② 层叠——`#root > AppFrame` 是 `position:relative`，body 里更早的定位元素先绘制 |
| 5 | 「`dsh-app://` 下 localStorage 不保证可用」 | **可用** | scheme 以 `standard:true, secure:true` 注册（`main.js:11880`），`open-sea-skin`/`better-sidebar` 两个生产插件都在用。仍建议文件为真源，见 D3 |
| 6 | 「音频纹理 512×2，第一行 L 第二行 R」 | **错** | 512×2 是**图像 pass 的音频输入纹理**：row0 = 频谱、row1 = 波形。音频输出是「每像素一个采样 + readPixels 回读」。v1 不做可视化，与输出编码无关 |
| 7 | 「透明化用 `--dsw-alias-*` token」 | **成立，且更好** | 0.2.1-rc.3 里 AppFrame 的表面颜色**全部走 token**（`ui-layout:73`：`.frame{background:var(--dsw-alias-bg-base)}`、`[data-windows-titlebar] .frame{background:var(--dsw-specific-sidebar-fill)}`、`.sidebarCol{...sidebar-fill}`），而 `theme.overrideTokens` 会把覆盖值**内联写到 `body.style`**（`ui-layout:548-569`）→ 滑块可以实时生效，不必学 open-sea-skin 打 `!important` 硬编码类名（其中 2 个 token + 4 个桌面类名在本版根本不存在） |
| 8 | 「三条路线：A 原生 slot / B index-inject / C 扩展」 | **分类失真** | 真实三分法是：官方 `dsh.client` 插件（wallpaper-engine / bg-new / open-sea-skin 原生包）/ `index-inject` 覆盖层（**只有 video-skin 一例**）/ 改源码加 slot。**主流是 client 插件** |
| 9 | 「open-sea-skin 零依赖」 | **错** | 它内置 three.js 0.178 + TSL + 字体（≈1.3MB）。我们的零依赖结论仍然成立，但别拿它当证据 |
| 10 | 「24 个作品基本都是纯程序化单 pass，声音标注准确」 | **未核验** | 本机对 shadertoy.com 恒 403（Cloudflare，实测首页也是 403）。抽样 6 个里 4 个旁证为真、2 个（`fXc3RB`/`ssjyWc`）零证据。→ 24 条必须逐条核验，别写进承诺 |
| 11 | 「许可证 = 默认 CC BY-NC-SA，不能随 MIT 发布」 | **方向对，措辞错** | ShaderToy 条款原文是**作者决定**许可证，**不声明才落到默认 CC BY-NC-SA 3.0**。结论不变：NC/未声明作品不能进 MIT 公开包 |

## 2. 推荐实现方式

### 2.1 四层结构

```
Electron 桌面壳 (dsh-app://app/)
  └─ Host 插件 (Node)  —— 只做两件事：静态资源路由 + 状态读写
       ├─ GET /shader-skin/*            读盘返回 player.html / ui.html / *.js / presets/*.json（no-cache）
       └─ GET|PUT /shader-skin/state    读写 $DSH_HOME/shader-skin.json（临时文件 + rename 原子替换）
  └─ Client 插件 (浏览器, dsh.client)  —— 薄壳(~150 行)，负责挂载与桥接
       ├─ 建 <iframe id=bg-skin>  → body 首子节点, fixed/inset:0/z-index:-1/pointer-events:none
       ├─ 注入玻璃 <style> + ctx.theme.overrideTokens()  ← 滑块改变时重设
       ├─ 悬浮入口（小圆钮 + 面板）与宿主的 mousemove / 可见性 / 主题 双向转发
       └─ 可选：向 settings.section 注册一个"Shader 背景"设置页
  └─ iframe 渲染器 (player.html, 单文件零依赖)  —— 真正干活
       ├─ WebGL2 mini runtime：GLSL 预处理 / uniform / FBO 多 pass / 音频
       └─ postMessage 协议：init / params / mouse / theme / pause / reset → ready / error / stats
```

**关键分工原则：客户端壳越薄越好，所有会反复改的代码都放在 Host 静态路由后面读盘提供。** 理由见 §3。

### 2.2 为什么是这三条

- **为什么不要 index-inject**：桌面注入表是启动快照（§1#1），改一次重启一次；且 Host 侧拿不到 `theme` 服务，做不了动态玻璃。
- **为什么宿主侧要一个 Client 插件**：`theme.overrideTokens` / `slots` / `locale` 都是 **Client 服务**，只有 client 半能用；client 半还能直接操作 DOM（`open-sea-skin` 生产先例）。
- **为什么渲染器放同源 iframe**：编译失败 / JS 异常 / 内存泄漏止于子文档，`location.reload()` 即重启；player 可以独立打开调试。（**注意**：iframe 隔离不了 GPU 进程崩溃——这个风险要单独兜，见 §7。）
- **为什么零依赖自研**：ShaderToy 代码本来就是 GLSL 文本 + 标准 uniform，three.js 帮不上忙还带 1MB+；不选 WebGPU 是因为它只吃 WGSL，转译链不可控，且 Electron/Windows 上可用性不如 WebGL2。

### 2.3 透明化怎么做（项目生死点）

三步，全部有源码依据：

1. **`ctx.theme.overrideTokens('shader-skin', { '--dsw-alias-bg-base': {light, dark}, '--dsw-specific-sidebar-fill': {light, dark}, … })`**
   值必须是 `{ light, dark }` 成对字符串（否则运行时抛教学错）。它把值内联到 `body.style`，能压过基础样式表，从而让 AppFrame / 侧栏 / 中栏变半透明。
2. **`<style>` 补丁**（只在 token 表达不了的地方）：弹层/对话框保持不透明、必要时补 titlebar 条与 rightbar 列的规则。
3. **`<iframe>` 的透明度**用 `opacity` 一个值搞定，不要用多层覆盖色凑。

> **[已实测，结论见 §9.3-9.4]** 把 `--dsw-alias-bg-base` + `--dsw-specific-sidebar-fill` 设成 rgba 半透明的做法**行不通**：外壳是十几层嵌套表面、每层都画同一个 token，alpha 相乘后背景几乎全黑，且层数随页面变化、无法用固定补偿救回。落地版改成：两个 token 设**全透明**，暗色滤镜由播放器在着色器输出上画唯一一层（`tintMix` = 玻璃不透明度），滑块只发 `params`、不碰 token。
> 与 open-sea-skin 的差异：**不覆盖 `--dsw-alias-bg-layer-1/2/3`**（卡片、输入框保持实体）→ 可读性最稳。

### 2.4 持久化

- 真源：**`$DSH_HOME/shader-skin.json`**，Host 用 `node:fs` 写（写临时文件 + rename），Client 走同源相对路径 `fetch('shader-skin/state')`。
- 桌面下 `dsh-app://app/shader-skin/...` 会被 shell 转发到 Host 的 HTTP 服务（`main.js:12406-12413`），所以同源 fetch 成立；生产先例 `dsh-better-sidebar` 的 `/sidebar/api/*`。
- **不要**用 `__DSH_TRANSPORT__.streamBaseUrl` 发 HTTP（那是 Host 真实 origin，跨源且无 CORS 头）。
- localStorage 只做缓存（面板位置、上次 tab），不作为库的真源——清站点数据/重置 profile 会丢。

### 2.5 设置界面（最终形态：侧边栏 → 整页）

| 入口 | 承载 | 状态 |
|---|---|---|
| 左栏「Shader 背景」→ `main` 整页 | 全部：开关、作品切换、玻璃/亮度/模糊/分辨率/帧率/速度/音量、背景库（导入/改名/删除） | ✅ 已实现（原计划的「右下角小圆钮 + 浮层面板」已废弃，见 §9.5） |

> 整页 iframe（`/shader-skin/panel.html?mode=main`）内容仍走 Host 静态路由 → 迭代只需刷新，不用重启。**不用** `settings.section`：`sidebar.panellist` + `main` 更接近原生面板的交互（点左栏一行、主区域整页），也不需要写 React 组件。

## 3. 开发循环：这是最大的效率优化

DSH 各层的热更能力是**分层的**（[核验]）：

| 改动位置 | 生效方式 | 代价 |
|---|---|---|
| Host 静态路由后面的 `player.html` / `*.js` / `*.css` / `*.json`（**读盘 + no-cache**） | **刷新页面即可** | ≈1 秒 |
| Client 插件 `client.js` 内容 | host 每 500ms 轮询文件 → SSE `/plugins/events` → 浏览器热替换 | 免重启（桌面端 SSE 是否通 **[待实测]**，不通就整机重启） |
| Host 插件 `index.js`（路由/apply 逻辑） | Host HMR 可能热更 | 若失效则整机重启 |
| 新增/启用插件、改注入行 | **整机重启** | 15 秒 |

**结论**：把渲染器、UI、预设全部放进 Host 静态路由，插件本体（Host+Client）写成一次成型、尽量不动的薄壳。**日常改 shader/调样式只刷新页面**，这是本项目最重要的工程决策。

## 4. 决策（✅ 已定稿 2026-10-26）

**D1 = A**（Client 插件 + Host 静态路由 + iframe）·
**D2 = A**（只透底壳，卡片与输入框保持实体）·
**D3 = A**（用户浏览器 Export JSON → 本地文件夹自动导入；M0/M1 先用自写 shader）·
**D4 = A**（合并为 4 个滑块：玻璃不透明度 / 模糊 / 缩放 / 速度，另有音量+静音）·
**D5 = A**（按 M0→M1→M2，音频留 M2）·
**D6 = A**（装完默认开启第一个背景，默认低亮度 + 30fps）。

### 4.1 由决策直接得出的实现口径

- 玻璃只覆盖 `--dsw-alias-bg-base` + `--dsw-specific-sidebar-fill`（+ 必要的 `<style>` 补丁），**不动** `bg-layer-1/2/3`，让卡片/输入框保持实体。
- 参数：`glass`（0.40–0.90，映射桌面壳 alpha）、`blur`（0–12px，默认 0）、`scale`（0.5–2 + 「适应全屏」）、`speed`（0–2，默认 1）、`volume`（0–1）+ `muted`。
- 预设来源：M0/M1 随包内置 2–3 个**自写** shader（MIT）；`$DSH_HOME/shader-skin/presets/*.json` 目录扫描 → 你导出的 Shadertoy JSON 丢进去即入库；公开包不含任何 ShaderToy 作品代码。
- 音频：M2 才动，验收必须用一个**确认有 sound pass** 的作品。

## 5. 优化空间（按收益排序）

1. **开发循环**（§3）：静态资源读盘 + no-cache → 刷新即迭代；插件壳一次成型。**收益最大**。
2. **玻璃用官方 `theme.overrideTokens`** 而不是 open-sea-skin 那套 `!important` + 硬编码 CSS-module 类名：更稳、更短、切亮暗主题自动跟随、滑块实时生效。
3. **音频大块回读**：512 采样逐块 = 每秒 86 次同步 `readPixels`（每次强制 flush GPU）。改成 **4096 采样/块（≈10.8 次/秒）+ 双通道 16bit 打包 + 500ms 预缓冲 + AudioBufferSourceNode 前瞻调度** → 回读开销降一个数量级，且背景音乐不怕延迟。AudioWorklet 留作 v2。
4. **模糊分级**：低分辨率渲染只给「柔」（省填充成本，scale 0.5 → 片元 25%），CSS `blur()` 才给「糊」；blur=0 时**完全不加 filter**（不设 will-change）。默认 0。
5. **可读性在渲染器内部解决**：在 player 里做 dim/tint 混合（暗色乘 ~0.5、亮色向 `#ececec` 混），零额外合成成本；不用额外叠覆盖层。
6. **背压与省电**：可见性暂停、失焦降到 30fps、电池模式 DPR 1.0、`prefers-reduced-motion` 进静态模式、自适应分辨率（EMA 滞回）、软渲染（SwiftShader/WARP）强制降档。
7. **预设按需加载**：shader 代码拆成 `presets/*.json` 单条 fetch，不进 JS bundle —— 库再大也不拖慢启动，且方便你随时替换 .json。
8. **切换零白屏**：编译完成前保留上一帧，失败回退旧作品；编译用 `KHR_parallel_shader_compile` 轮询，避免卡主线程。
9. **导入即体检**：粘贴/导入时在 1×1 离屏 WebGL2 上真编译 + 静态扫描（外部纹理 / cubemap / 键盘通道 / `mainVR` / `#define iTime` / ES3 保留字）→ 直接给「能跑 / 需要图片输入不支持 / 高负载将自动降档」的结论，而不是等用户点了才炸。
10. **崩溃兜底**：iframe 隔离不了 GPU 进程崩溃 → 崩溃计数持久化，连续 2 次自动进安全模式（关背景 + 提示），并提供一键关闭。

### 9.2 真实作品实测

- 用户提供 **Seascape（TDM，CC BY-NC-SA 3.0）**：本地导入 `$DSH_HOME/shader-skin/presets/seascape.glsl`，在播放器里 `?preset=local/seascape.glsl` 直接 ES3 编译通过、画面正确（`docs/verify/seascape.png`）。**该作品不进包、不进仓库**，只作为本机用户背景（已写入 `$DSH_HOME/shader-skin.json` 并设为当前背景）。

### 9.3 卡死 / 失效复盘（重要，别再踩）

桌面端前端两次被卡死，另外还有两次「滑块像死的」——根因有四条，三条出在 **client 半** 的框架用法上：

1. **`:has()` 锚定整树**：玻璃补丁用过 `body #root div:has(> [data-shell-overlay])` 这类选择器。切换侧边栏面板时 Chromium 触发整棵 `#root` 的样式失效重算，界面像死机。→ 已删除所有 `:has()`。
2. **主题 observer 反馈环**：监听 `body[data-ds-dark-theme]` 时，回调里调用 `applyGlass()` → `theme.overrideTokens()` 会发 `theme/change` → presenter 重新写一遍该属性 → 再次触发 observer → **无限循环烧 CPU**。改代码触发热重载后尤其明显。→ 回调只做「值真的变了才转发」，绝不在回调里改 token；玻璃 token 现在只在启动时写一次，滑块完全不再碰 token。
3. **面板消息全被丢弃（「滑块失效」真凶）**：`postMessage` 的事件里 `event.source` 是 iframe 的 **`contentWindow`（WindowProxy）**，而 client 半把 **`<iframe>` 元素**存进 `panelFrames`，再 `panelFrames.has(event.source)` 判断——永远 false。于是设置页发来的 `params` / `preset` / `audio-resume` 全被静默丢掉：滑块拖了没反应、切作品不生效，但**状态文件照常保存**（那是面板自己 PUT 的），看起来像「设置保存了却不起作用」。→ 改为按 window 存（`panelWindows`），发送时统一 `target?.contentWindow ?? target`。
4. **半透明 token 层层相乘（「背景太黑」真凶）**：外壳并非两层表面——AppFrame、中列、各页面根、Windows 标题条等**十来个嵌套容器**都画 `var(--dsw-alias-bg-base)`。每层 alpha 0.225（对应 glass=40%）时只剩 `0.775^n` 的背景可见，实测亮色海面被压到约 7% 亮度，看着就是「一片黑 + 隐约波纹」。→ 玻璃模型换成一层的方案，见 9.4。

**安全阀**：`$DSH_HOME/shader-skin.safe` 存在时，client 半跳过所有注入 `#root` 的 UI（只留背景层）；Host 暴露 `/shader-skin/safe-mode` 供读取。

### 9.4 玻璃模型 v2：外壳全透明 + 播放器画唯一一层滤镜

旧模型（`--dsw-alias-bg-base` / `--dsw-specific-sidebar-fill` 设成半透明 rgba，再按「两层」做 `a = 1 - sqrt(1 - glass)` 补偿）在真实 DOM 上必然过暗，因为层数不是 2 而是十几层，且数量随页面结构变化，**参数无法补偿未知层数**。

新模型把两件事拆开：

1. **外壳表面**：两个 token 直接设成全透明（`rgba(9,12,16,0)` / `rgba(255,255,255,0)`），背景层因此成为唯一的底；token 只在启动时写一次，拖滑块不触发 `theme/change`，没有重排风暴风险。
2. **唯一的滤镜**：由播放器在着色器输出上做一次 `mix(color * brightness, veil, glass)`（`dim` + `tint` + `tintMix`），一层合成、与 DOM 深度无关。`glass` 滑块 = 这层滤镜的不透明度；`brightness` 滑块 = 画面亮度乘数（0.3–1.8）。

配套改动：

- 播放器 `dim` 上限从 1.0 放到 2.0，并新增 `lookExplicit`：父页面一旦发过显式 look，主题消息不再把它重置成「按主题猜的默认压暗」；
- 主题消息提前到 `init` 之前发，初始化参数最后到达，保证「显式 look 赢」；
- 设置页新增「背景亮度」滑块，`defaults.json` 的 `glass` 默认 72→60、新增 `brightness: 100`。


### 9.5 侧边栏原生入口（改为整页）

`sidebar.panellist` + `main` 的注册形态按真实先例核对（`slots.inject(key, () => slots.register({name, id|key, order, label}, Component))`）。第一版曾把弹窗面板嵌进 `main` 且带着上面两条卡死根因，导致点侧边栏就卡死；两条根因修掉后改为：

- **去掉悬浮弹窗**（右下角圆钮整个移除，缩小了失败面）；
- 侧边栏一行「Shader 背景」→ `main` 面板渲染 `/shader-skin/panel.html?mode=main`，在**主区域整页展示**（页头 + 参数 / 背景库两个页签），iframe 用 `position:absolute; inset:0` 填满主列（不依赖父容器百分比高度）；
- 仍由 `ENABLE_SIDEBAR_ENTRY` 常量控制，`$DSH_HOME/shader-skin.safe` 可一键跳过注册。

### 9.6 交互细化：iMouse 拖拽 + 代码页（v0.2.0）

**iMouse 只在拖拽时驱动，而且必须从「空白处」按下**：旧版把每个 `pointermove` 都转发给播放器，鼠标划过界面背景就跟着搅动，抬手后 `iMouse.xy` 还在动。现在的判定分两层：

1. `pointerdown` 的命中目标若落在 DSH 自己的控件/可选文字上（`button/a/input/textarea/select/summary/label/[contenteditable]/[role=button|tab|menuitem|option|dialog|listbox]/[data-shell-overlay]/[data-rightbar-col]/[data-shell-bottom]`，或祖先链上 `user-select: text`）→ 整次拖动不接管背景；
2. 拖动过程中一旦出现文本选区（`getSelection().type === 'Range'`，即复制/选中回复）→ 立即中止并丢弃这一帧的鼠标消息。

按下只记录 anchor，真正移动才开始转发；松开/取消/失焦 → 发**一条** `[…, -|anchor|]`，让着色器按 ShaderToy 语义看到 `iMouse.z < 0` 的「已松手」状态。

**卡片透明度三档（`panels`）**：外壳（`bg-base` / `sidebar-fill`）永远全透明，但卡片、代码块、弹层、菜单、输入框默认仍是实体色，背景透不进去。新增 `panels` 参数 → 覆盖 `--dsw-alias-bg-layer-1/2/3/4`（alpha 0.62 / 0.22）与 `--dsw-alias-bg-overlay`、`--dsw-specific-menu`、`--dsw-specific-input-major`（alpha 层值 + 0.32，保证弹层/菜单还能读）。三档 = `opaque`（不覆盖，默认）/ `half` / `clear`。这一项会真的重设 token（会发一次 `theme/change`），所以按「token 集合签名变化时才重新发布」处理：拖玻璃/亮度滑块不会触发重设，只有切换档位才会。

**代码页（第三个页签）**：显示**当前正在运行**作品的 Image / Sound 源码，可直接编辑 →「保存并运行」（Ctrl/⌘+S 同效）：

- 保存 = 写 `$DSH_HOME/shader-skin.json` → 通知 client 重新 `sendInit` → 播放器重新编译；编译错误（带 GLSL 行号）显示在按钮下方；
- 内置作品只读：保存时自动 `addEntry` 出「<原名>（我的副本）」并切过去，包内文件不动；
- 「放弃修改」重新读取已保存版本。

顺带修掉一个潜伏的竞态：`setActive` 以前先发 `preset` 消息、320ms 后才防抖保存。client 收到 `preset` 会 `reloadState()` 重新读盘——新条目**还没落盘**，于是 `resolvePreset` 找不到它、回落到第一个内置作品，出现「切到新导入的作品却显示极光」。现在 `setActive` / 删除 / 导入都先 `saveNow()`（立即 PUT）再发消息。

**已知坑：`precise` 在 WebGL2 里不合法**。ShaderToy 上防止驱动 FMA 收缩、让共享晶格点同哈希的写法用 `precise float h = …`，但 `precise` 是 GLSL 4.0 / ESSL 3.20 的限定符，WebGL2 只有 ESSL 3.00，实测报 `ERROR: 0:39: 'precise' : undeclared identifier`（ES3/ES1 都挂）。等价修法是**整数哈希**（`ivec2 + uint` 位混合），不需要限定符，且共享晶格点天然同哈希。用户的海面（Seascape）已按此替换 `hash`/`noise` 两份函数并验证 ES3 编译通过、画面正常。

### 9.7 启动自愈：为什么「每次重启都要手动关掉再打开插件」

**根因（客户端插件启动竞态）**：桌面端 client 插件按 loader 行**并发激活**（`modules.entries.start` 之后 `await loader.await()`，每个 fiber 只等自己在 `inject` 里声明的依赖）。我们 client 半声明 `inject: []`，所以可能比 `theme` / `slots` 这两个服务**先**激活。旧代码在 effect 建立时一次性取值：

```js
const theme = ctx.get('theme')   // 此时可能还是 undefined
const slots = ctx.get('slots')
```

服务晚到之后这个引用永远是 `undefined` → `applyGlass()` 直接 return（外壳 token 没被覆盖 → **背景被不透明的壳挡住，看起来像插件没启动**），`registerSidebar()` 也直接 return（**左栏没有入口**）。而手动关掉再打开插件会重新跑一遍 `apply`，那时服务都就绪 → 一切正常。这就是「每次重启都要手动开关一次」的全部原因。

**修法（三层）**：

1. **不再缓存服务引用**：`service(name)` 每次 `ctx.get(name)` 现取，`applyGlass()` / `registerSidebar()` 里都现取 `theme` / `slots`；`require('react')` 也做成惰性重试（模块表可能后到）。
2. **启动时等一等**：`waitForService('theme' | 'slots', 15s)` 轮询（50ms），等到再应用玻璃、注册侧栏，不再依赖「碰巧先激活」。
3. **有界自愈**：`verifySurface()` 在启动后 0/250/700/1500/3000/6000/10000ms 各跑一次，外加首次 `focus` / `pointerdown` / 回到前台时各跑一次，检查并修复：
   - 背景 iframe 不存在或被壳重绘弄掉 → 重建；
   - 玻璃 token 被 body 样式重置覆盖 → 重新应用（`tokensIntact` 逐 token 检查 inline 值是否存在）；
   - 播放器没收到 init / 没上报 `ready` → 重发 init（上限 4 次、3s 重试）；`ready` 消息现在会被记录；
   - 侧栏行当时因 `slots` 缺失没注册上 → 补注册。
   这些检查只做「缺了才补」，不会形成 `theme/change` 循环（自愈共 7+3 次后稳定）。
