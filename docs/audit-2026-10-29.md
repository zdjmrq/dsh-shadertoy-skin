## 四、第二轮审查（同日补充）

用户提出「按音乐和图像两者最晚结束的一方判断」后重新审了一遍时间轴、状态保存与纹理生成，又修了 4 项（#13–#16），并整理出后续可做项。

### 本轮修复（详见上表 #13–#16）

- **联播周期**：音画都已知结束点时按 `max(画面, 音乐)` 一起回绕（1× 速度下）。这是「最晚结束一方」的落地方式，修掉了 `take-on-me` 音乐在结局画面上提前重播的真实不同步。
- **速度单位**：倍速下联播周期会变成不同的真实秒数，改为只在 1× 启用，其他速度退回独立循环。
- **恢复日志双序列化**：自动保存不再把整份状态序列化两次。
- **生成纹理缓存**：font SDF / noise / 程序化城市跨作品复用，切换不再重算。

### 发现但未改（值得做、需要产品或用户拍板）

| 项 | 类型 | 说明 |
|---|---|---|
| 键盘通道在背景中不可用 | 功能缺口 | `keyboard` 纹理只在独立预览页接收按键；背景里为了不抢 DSH 输入一直保持松开。要做需明确「仅在画面区域聚焦时转发」的规则，风险高 |
| 窗口失焦不降帧 | 省电优化 | 只有 `document.hidden`（最小化/切标签）会跳过绘制；同屏失焦仍按 fps 跑。可加「失焦降到 10 fps」选项，但有人会把 DSH 放副屏看背景，需默认值决策 |
| 每作品独立 fps/分辨率 | 小功能 | 现在 fps/scale 是全局；状态里已有 per-preset `overrides` 结构，加 UI 即可 |
| 背景库搜索 / 过滤 | 功能 | 200 条上限内只能滚动找 |
| 「循环方式」文案未体现联播 | UX | 设置页可加只读提示「画面 209 s / 音乐 180 s → 按 209 s 联播」，数据要从播放器回传 |
| 手动循环周期只重置画面 | 语义确认 | `loopSeconds` 手动模式目前只重置画面，音乐仍按自身时长循环；若期望音乐也按该周期回绕需要改语义（可能截断音乐） |
| 极端 ShaderToy JSON 的 buffer 通道映射 | 健壮性 | `parseDocument` 在 buffer pass 既无 `outputs[].id` 又无 `id` 时，通道映射可能落到最后一个 buffer；真实导出几乎不会出现，可加兜底 id |

### 性能开销现状（可核对）

- **每帧**：每个 buffer pass + image pass 各一次全屏三角形绘制；**没有逐帧 GPU 回读**。
- **画面结束检测**：2 Hz 的 16×16 GPU blit + 1 KB readback，仅在 auto + 无显式时长时运行。
- **键盘纹理**：从「每帧 3 KB 上传」降为「仅按键帧上传」。
- **音频**：每 93 ms 合成 4096 样本 + 读回 16 KB + JS 解码，实测约 10–12 块/秒；静音且时长已知时跳过合成，未知时长仍合成以探测结束。
- **纹理生成**：font SDF（两份 512² 八邻域距离场）约 200 万次迭代 + noise + city 只生成一次。
- **设置页**：自动保存 320 ms 防抖；恢复日志复用请求 JSON；滑块拖动不再重建背景下拉或整表序列化；详情只在行数变化时重建行号。
- **玻璃**：token 覆盖只在签名变化时应用；body 样式被改时合并到每帧一次修复，不在主题回调里递归。
- **内存边界**：多 pass 96 MB、纹理总量 1600 万像素、状态 2 MB、代码 1.5 MB、音频队列 32 块。
